## 1. 서론

### 1.1 목적 및 범위
본 문서는 사용자가 자신의 수입과 지출을 수동으로 기록하고 관리하는 모바일 앱 '머니로그'의 요구사항을 정의합니다. 외부 은행 연동 없이 사용자의 기기에만 데이터를 저장하는 '오프라인 우선' 방식과 미니멀한 기능을 통해 프라이버시 보호와 빠른 기록 환경을 제공하는 것을 목적으로 합니다.

### 1.2 용어 정의
| 용어 | 설명 |
| :--- | :--- |
| **수동 입력** | 외부 금융기관 API 연동 없이 사용자가 직접 금액과 내용을 입력하는 방식 |
| **카테고리** | 지출이나 수입의 성격(식비, 교통비, 월급 등)을 분류하는 단위 |
| **예산** | 특정 기간(월간) 동안 사용하기로 설정한 목표 지출 금액 |
| **로컬 저장** | 모든 데이터를 서버가 아닌 사용자의 스마트폰 내부 저장소에 보관하는 방식 |

### 1.3 참조 문서
1. [이동하]시스템정의서 : project1.md
2. [이동하]프로젝트관리계획서 : project3.md

## 2. 시스템 개요

### 2.1 소프트웨어 문맥도 (Context Diagram)
* **Actor (액터):** 사용자 (User)
* **System (시스템):** 머니로그 시스템 (MoneyLog System)

#### 2.1.1 Actor Table
| Actor | Role |
| :--- | :--- |
| **사용자** | 매일의 지출/수입을 입력하고, 설정한 예산 대비 소비 현황 및 통계를 확인하는 주체 |
| **시스템** | 사용자가 입력한 정보를 로컬 DB에 저장하고 월별 리포트 및 예산 알림을 생성함 |

### 2.2 기능 분류 및 설명

#### **[U_01: 지출/수입 내역 입력]**
| 항목 | 내용 |
| :--- | :--- |
| **Use Case Name** | 지출/수입 내역 입력 |
| **ID / 중요도** | U_01 / High |
| **Primary Actor** | 사용자 |
| **Brief Description** | 사용자가 발생한 금액, 날짜, 카테고리를 선택하여 가계부에 기록한다. |
| **Trigger** | 사용자가 메인 화면에서 '내역 추가(+)' 버튼을 누른다. |
| **Normal Flow** | 1. 사용자는 금액을 입력하고 수입 또는 지출 타입을 선택한다.<br>2. 발생 날짜와 해당되는 카테고리를 선택한다.<br>3. '저장' 버튼을 누른다.<br>4. 시스템은 로컬 DB에 데이터를 저장하고 메인 화면으로 돌아간다. |
| **Exceptional Flows** | 2.a1 : 필수 입력 항목(금액, 카테고리 등)이 누락된 경우, 시스템은 경고 메시지를 출력하고 저장을 중단한다. |

#### **[U_02: 내역 조회 및 필터링]**
| 항목 | 내용 |
| :--- | :--- |
| **Use Case Name** | 내역 조회 및 필터링 |
| **ID / 중요도** | U_02 / High |
| **Primary Actor** | 사용자 |
| **Brief Description** | 날짜별 또는 카테고리별로 과거의 수입/지출 기록을 필터링하여 조회한다. |
| **Trigger** | 사용자가 내역 리스트 상단의 '조회 설정' 또는 '필터' 버튼을 누른다. |
| **Normal Flow** | 1. 사용자가 조회하고자 하는 기간(날짜 범위) 또는 특정 카테고리를 선택한다.<br>2. 시스템은 로컬 DB에서 조건에 부합하는 내역을 검색한다.<br>3. 시스템은 필터링된 결과를 날짜순으로 리스트 화면에 출력한다. |

#### **[U_03: 월간 요약 리포트]**
| 항목 | 내용 |
| :--- | :--- |
| **Use Case Name** | 월간 요약 리포트 |
| **ID / 중요도** | U_03 / High |
| **Primary Actor** | 사용자 |
| **Brief Description** | 한 달 동안의 총 수입, 지출 및 잔액을 수치와 차트로 시각화하여 보여준다. |
| **Trigger** | 사용자가 '하단 메뉴'에서 '리포트/통계' 탭을 선택한다. |
| **Normal Flow** | 1. 시스템은 현재 설정된 월의 모든 수입과 지출 데이터를 합산한다.<br>2. 시스템은 총액과 카테고리별 소비 비중을 계산한다.<br>3. 계산된 수치와 통계 차트를 화면에 표시한다. |

#### **[U_04: 카테고리 커스터마이징]**
| 항목 | 내용 |
| :--- | :--- |
| **Use Case Name** | 카테고리 커스터마이징 |
| **ID / 중요도** | U_04 / Medium |
| **Primary Actor** | 사용자 |
| **Brief Description** | 사용자가 자신의 소비 패턴에 맞게 카테고리 이름을 추가하거나 수정한다. |
| **Trigger** | 사용자가 설정 메뉴에서 '카테고리 관리'를 선택한다. |
| **Normal Flow** | 1. 사용자가 '추가' 버튼을 누르거나 수정할 기존 카테고리를 선택한다.<br>2. 카테고리 명칭과 대표 아이콘을 설정/변경한다.<br>3. '완료' 버튼을 누르면 시스템은 카테고리 설정을 업데이트한다. |

#### **[U_05: 예산 설정 및 알림]**
| 항목 | 내용 |
| :--- | :--- |
| **Use Case Name** | 예산 설정 및 알림 |
| **ID / 중요도** | U_05 / High |
| **Primary Actor** | 사용자 |
| **Brief Description** | 월간 목표 예산을 설정하고, 지출 입력 시 예산을 초과하면 경고를 제공한다. |
| **Trigger** | 사용자가 예산을 설정하거나, 새로운 지출을 입력하여 예산 한도에 도달할 때 발생한다. |
| **Normal Flow** | 1. 사용자가 이번 달 쓸 목표 금액(예산)을 입력하여 저장한다.<br>2. 지출 내역이 입력될 때마다 시스템은 (기존 지출 + 현재 지출)과 예산을 비교한다.<br>3. 총 지출이 예산을 초과하는 경우, 시스템은 화면에 경고 알림 팝업을 띄운다. |

### 3.3 동적 분석 (순차 다이어그램)
* **내역 조회 흐름:**
    1. **사용자 -> UI:** 특정 월의 리포트 보기 클릭
    2. **UI -> Controller:** 해당 월의 내역 데이터 요청
    3. **Controller -> Local DB:** `getTransactionsByMonth()` 쿼리 실행
    4. **Local DB -> UI:** 데이터 반환 및 통계 차트 렌더링
